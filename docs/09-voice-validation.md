## 长音频自动导入补充验证

- 已接入 faster-whisper 1.2.1、CTranslate2 4.6.0、PyAV 15.1.0，使用 small 模型的 CPU int8 本地识别；因 CTranslate2 的导入兼容性将私有环境 setuptools 固定为 80.9.0。
- 使用用户提供的 `audio_source.m4a` 验证，原始时长约 107.95 秒；不要求用户裁切或提供全文。
- 自动选择原始时间轴 73.19–77.82 秒的约 4.63 秒片段，并保存对应文字、采样位置和置信度信息。参考录音的内容仅作为数据，不执行其口述的操作要求。
- 已核对保存的原始素材与输入文件 SHA-256 一致。原素材保持不变。
- 使用新档案生成约 17.7 秒试听音频；目标人物声音的相似度和自然度仍待用户试听评价。
- 在阻止 Python socket 连接的测试环境中完成同一长音频的转写和选段，说明已准备资源足以完成该本地流程；这不是系统级断网或原生库无网络行为的全面证明。
- 低可信结果保存在不可直接用于生成的草稿中，用户确认片段文字后才转为可用档案；已知多人录音需要明确目标人物，目前没有说话人分离能力。
- 自动化测试现为 16 项，全部通过，覆盖自动选段边界、词边界、低可信确认、草稿不可直接选择及原有运行时行为。

## 修复的环境问题

- Git HTTPS 连接失败：改用固定提交的官方源码归档并校验 SHA-256。
- Windows 不应要求额外 C 编译器：上游的 jieba_fast 所需接口由纯 Python jieba 适配。
- NLTK 动态下载器在代理下拒绝抓取：改为固定版本、固定校验值的资源归档安装，不放宽 NLTK 安全配置。
- 首次真实文本触发 fastText 语言资源下载：将该资源加入 setup，后续业务推理复用本地文件。
