# 统一初始化 Skill 设计

[English](../en/07-setup-skill-plan.md) | [简体中文](07-setup-skill-plan.md)

状态：已实现统一 doctor、功能注册与 voice 初始化的 alpha 版本；其他功能尚未注册，配置迁移和资源清理尚未实现。以下保留整体设计目标。`codoop-setup` 是整个插件的初始化与配置入口，不是 GPT-SoVITS 专用安装器，也不是通用系统管理工具。

## 职责

负责本插件的环境检查、共享目录与偏好配置、按功能安装依赖及资源、版本校验、状态查询和有界修复。后续调研、写稿、字幕和视频模块需要的初始化配置统一在这里接入，业务执行仍由对应 skill 完成。

用户无需知道内部功能标识或安装命令。功能 skill 根据任务声明所需能力，由 setup 只准备缺失部分；成功后返回原任务继续执行。用户单独请求初始化时，可检查现状并询问准备使用哪项已发布功能，不默认安装所有模型。

## 组织方式

- `SKILL.md` 只包含共同流程、功能选择与结果交接。
- `references/` 按功能保存必要配置和故障说明，仅在处理对应功能时读取。
- 共享 runtime 提供统一 doctor、配置存取、资源校验与安装调度。
- 各功能的初始化实现按模块注册，不把全部安装逻辑堆在 skill 正文或一个巨大脚本中。

首批只注册 voice；后续模块完成实现后再注册 research、script、alignment、video 等初始化项，不发布空实现。功能初始化允许“不需额外安装”的结果，例如某写作流程直接使用宿主 Agent 的现有能力。

## 功能初始化约定

每个注册项声明：功能 ID、配置结构版本、支持的平台与后端、依赖版本、所需资源及校验信息、前置初始化项、就绪检查、准备与修复方法。依赖关系应可检查且无环。

统一执行过程：

1. 读取现有配置，检查所需能力和可用硬件。
2. 计算最小准备范围，包括确实需要的共享依赖。
3. 说明必要的下载量、保存位置及需要用户补充的内容，沿用已有授权与宿主权限。
4. 准备缺失部分，保存进度；重复调用复用已有资源，失败后可继续。
5. 执行真实就绪检查，记录版本与状态。
6. 返回结构化结果，交回请求方继续业务任务。

初始化结果至少包含功能 ID、状态、缺失项、配置引用、必要下一步和错误。状态区分 ready、needs_setup、needs_input、unsupported、failed。只检查时不自动安装；明确执行任务或初始化时，才在授权范围内准备环境。

## 配置边界

共享配置保存数据根目录、缓存目录及通用偏好；功能配置按命名空间保存，例如 voice 的模型与后端、video 的渲染资源。用户不需要手工编辑配置文件，Agent 通过固定命令读取和修改。

调整某一功能配置不覆盖其他功能。共享资源记录被哪些功能引用；修复、更新或清理不能破坏仍在使用的配置。不同后端依赖冲突时使用独立环境，不强制一个解释器兼容所有模块。

用户任务输入、稿件、参考声音和成品不属于初始化配置，由业务模块管理。账户登录或密钥只在未来确有相关功能时另行设计，不能提前要求用户提供，也不能在普通状态输出中暴露敏感内容。

## 验收

- 请求配音只准备 voice 所需资源，不安装调研或视频依赖。
- 重复初始化及中断恢复不会重复下载有效资源或覆盖用户配置。
- 新增一个功能只需增加其注册项及实现，无须改写其他功能的初始化流程。
- 某功能失败不使其他已就绪功能变为不可用。
- 更新共享目录配置时保留其他功能配置；资源迁移须检查实际文件后再更新引用。
- 只完成下载但未通过就绪检查时，不报告成功。
- 功能 skill 可从 setup 结果继续原任务；宿主不能嵌套调用 skill 时，按其说明执行同一套本地脚本，不能依赖不存在的工具。
