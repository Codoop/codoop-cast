# 开源插件与 Agent 使用体验设计

[English](../en/05-plugin-experience.md) | [简体中文](05-plugin-experience.md)

> 状态说明：本文保留对应开发阶段的计划或验证记录。当前已实现能力与发布缺口以 [Alpha 发布状态](29-release-readiness.md) 为准；首次使用见 [安装指南](28-install-and-first-video.md)。

状态：设计方案，尚未发布。本文优先修正早期单机开发视角：codoop-cast 是面向其他用户分发的开源插件，以 skills 为入口，通过本地脚本完成任务，不要求用户部署 HTTP 服务。

## 用户旅程

安装轻量插件 → 用自然语言描述任务 → Agent 检查环境 → 首次按需准备依赖 → 本地执行 → 返回可用文件。

用户无需学习 Python、模型启动命令或内部模块调用。模型下载与初始化有实际成本，不能宣称安装插件后在任意硬件上都能立即生成语音。宿主必须能执行本地进程并访问用户选定的文件；纯云端且无法访问本机的 Agent 不在首版范围。

能力范围取决于用户完成内容制作所需，而非上游库提供了什么。声音模块只做参考声音复用与稿件配音，不提供训练、微调及训练数据管理。只有一个声音时自动使用，多个且未指定时才询问；技术配置由插件管理。

示例：首次说“用这段声音读这篇稿子”，Agent 准备配音环境，插件自动从原始录音选段并本地识别文字，返回 WAV；仅识别不可靠时确认片段文字。以后说“用上次的声音读这篇”，自动复用档案。用户说“第二段重来”时，只重做对应段落。

## Skill 划分

以下早期表格由[独立 Skills 与工作流交接契约](13-skill-contracts.md)补充并更新：字幕、分镜、素材、HTML 场景和最终视频合成分别独立；所有输出以标准化制作包衔接。当前 setup、voice、subtitles 已实现本机 alpha 路径，其余尚未实现。

| 计划名称 | 用户意图 | 必要输入 |
| --- | --- | --- |
| codoop-setup | 为本插件各功能统一检查、初始化、配置与修复 | 必要时指定功能或数据盘 |
| codoop-voice | 保存声音档案、克隆配音、重做 | 首次参考音频和文字、朗读稿 |
| codoop-research | 调研话题并生成报告 | 话题或用户资料 |
| codoop-script | 将报告写成口播稿 | 报告，目标时长有默认值 |
| codoop-video | 制作视频 | 稿件或已有制作产物 |
| codoop-produce | 串联已实现能力 | 话题或已有中间产物 |

首批只交付 setup 与 voice，其余随模块完成再发布，不创建无法执行的占位入口。字幕已确定作为独立 skill，支持导入音频与稿件；具体边界以新交接契约为准。

setup 是插件级公共能力，按功能注册初始化项，首批仅实现 voice。后续功能复用同一入口，仅准备当前任务缺失的依赖及配置，不默认安装全部能力。职责与扩展方式见[统一初始化 Skill 设计](07-setup-skill-plan.md)。

名称和描述负责准确发现；SKILL.md 写关键流程和约束；详细参数放 references，重复操作交给 scripts。自动选择能力取决于宿主，显式调用方法按实际宿主说明。

## 分发结构

```text
codoop-cast/
  <Codex / Claude Code / Cursor 插件清单>
  skills/
    codoop-setup/SKILL.md
    codoop-voice/SKILL.md
  scripts/                  # 本地命令入口与环境引导
  runtime/codoop-cast/       # 共享 CLI、能力及模型适配器
  docs/                     # 维护者文档
```

这是规划结构，本次不创建技能或清单。Skills 指导 Agent，脚本确定性地完成检查、安装、执行及恢复。分发时验证共享代码随包提供且路径可定位；仅复制 SKILL.md 不等于完整安装。

参考 codoop-flow，同一套核心能力通过薄层清单适配 Codex、Claude Code 与 Cursor，并提供复制 skills 与 runtime 的备用路径。三类宿主均纳入适配设计，实际安装通过后标为支持，不虚构所有 Agent 通用的安装命令。详见[兼容计划](06-compatibility.md)。

OpenAI 官方提供 skills 与插件打包规范，技能包不强制依赖 MCP。具体清单与安装方式在发布时按目标版本核对：[插件打包](https://developers.openai.com/plugins/build/plugins)、[构建 skills](https://developers.openai.com/plugins/build/skills)。

## 按需安装

- 插件包包含代码与资源清单，不内置大型权重；只用写稿或调研不安装 GPT-SoVITS。
- 首次配音先检测系统、硬件、磁盘、依赖与模型；缺失部分由安装脚本准备。
- 使用插件专用环境，优先复用兼容解释器或准备独立运行时，不要求用户卸载系统 Python，不修改全局 PATH。
- 当前开发机按用户要求卸载 3.13 属于个人调整，不是对外安装步骤。
- 大型下载前说明预计体积与目录；沿用已有授权及宿主权限，不重复确认，也不隐瞒必要的权限提示。
- 固定依赖与模型组合，资源记录来源及校验值；安装有阶段进度、可恢复下载、完成标记，失败不能报告就绪。
- 修复仅针对插件私有环境；需要用户处理驱动等问题时说明具体原因。
- 硬件验证顺序已确定为 Windows + NVIDIA、Windows + AMD、Mac；后两者先调查再实机验证，不预先承诺可用。CPU 和 Linux 等其他路径单独标注验证状态。

## 目录与生命周期

插件代码视为只读、可升级；运行时、模型缓存、声音档案和作品存放在独立可配置目录，不能默认写入插件安装缓存或维护者的 E 盘路径。

显式配置优先，其次平台用户数据/缓存目录；首次大文件准备可选择其他磁盘并记住选择。插件升级不覆盖声音和作品；卸载插件不自动删除作品，缓存、运行环境和个人数据分别清理。

短期使用前台本地命令，工作进程在一次任务内常驻复用模型，任务结束释放显存，不要求永久守护进程。后续有批量性能需求再优化。

## Agent 执行约定

CLI 职责草案：`doctor`、`setup --feature voice`、`voice create`、`voice list`、`speech generate`、`speech retry`、`speech export`、`task status`。最终调用形式在打包验证后确定。

输出稳定 JSON：状态、任务 ID、下一步动作、错误类别、产物绝对路径；日志走 stderr 或文件。长任务持久化进度，Agent 根据宿主能力等待或恢复。用户不需要自行找到隐藏目录里的结果。

用户只需决定参考声音、稿件、修改内容与输出位置；模型路径、采样率、分段参数使用经过验证的默认配置。失败先执行有界诊断，无法恢复时才询问必要信息。

## 开源发布与验收

- 项目许可证待选定；发布前提供 LICENSE 与第三方许可说明，不将代码许可套用到模型、字体或素材。
- 说明联网下载与本地处理边界，默认不上传声音和作品，不添加未披露遥测。
- 干净环境安装验证覆盖：中文用户名、空格路径、非管理员账户、重复安装、中断恢复、插件升级及数据保留。
- 验证 skill 可发现、脚本可定位，不依赖维护者机器的路径或未声明全局工具。
- 标明已验证宿主和平台，未实现能力不列为可用。
- 验收以用户通过 Agent 获得成品为准，不能仅以模型启动成功为准。

第一个任务因此增加 setup skill、voice skill、CLI、按需安装与分发验证。内部函数和子进程协议保留，但不要求用户直接调用。
