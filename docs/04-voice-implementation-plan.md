# 声音复制与配音 Skill 实现计划

状态：已进入 alpha 实现。V0–V4 已有代码及本机推理验证；V5 已有 skills、清单与备用安装器，原生宿主安装尚未验证；V6 尚需真实目标声音试听和更多干净环境验收。以下为设计与实施依据，实际使用参见[运行说明](08-running-voice.md)。

## 产品目标与交付原则

最新体验修正：3–10 秒是当前 GPT-SoVITS v2 推理入口对内部参考片段的校验，不是用户导入素材的时长上限。已接入 faster-whisper small CPU int8 本地转写与自动选段；保存原录音及片段偏移，识别不可靠时返回草稿等待确认。暂不自动区分说话人，已知多人时需先明确目标声音。

补充实施步骤：本地识别/语音活动分段 → 按句子边界选取满足模型约束的片段 → 提取该片段的准确文字 → 保存原素材、片段偏移、片段音频与文字 → 交给已有配音流程。不能裁剪音频后继续沿用整段原文，也不能只按音量高低推断单一说话人。发现多人素材或低可信文字时，集中询问必要确认。输入过短或无可用语音时说明原因，不靠补静音伪造合格参考。

让用户通过 Agent 说“用这段声音读这篇稿子”，就能获得本地生成的音频。插件封装 GPT-SoVITS 所需的推理能力，不提供模型工具箱。

正常使用只包含：提供参考声音 → 输入稿件 → 获得音频。首次保存声音后可重复使用；不要求用户理解模型、分段、采样率、依赖或推理参数。不提供训练、微调和训练数据管理，也不安排相关后续能力。

用户不需要先手动运行 setup skill。配音 skill 检测到缺少环境时复用 setup 流程，再继续原任务；setup skill 仅为主动检查、安装和修复提供独立入口。

setup 属于整个插件的统一初始化能力，voice 只注册自己的依赖与配置，不拥有专用 setup。后续各 skill 可接入相同机制，详见[统一初始化 Skill 设计](07-setup-skill-plan.md)。

## 目标与已确认条件

对外分发要求见[开源插件与 Agent 使用体验](05-plugin-experience.md)。首个模块交付包含 setup 与 voice skills、稳定 CLI、按需安装脚本及干净环境验收；下文函数和进程设计属于内部实现，用户通过 Agent 使用。

Agent 参考 codoop-flow 适配 Codex、Claude Code、Cursor，共用一份 runtime；硬件按 Windows NVIDIA → Windows AMD → Mac 顺序验证，详见[兼容计划](06-compatibility.md)。本机 Python 3.10 是开发配置，其他硬件后端允许采用其验证过的独立 Python 版本。

用户导入原始录音，插件自动选择参考片段并识别文字，保存声音档案；输入中文稿件后，在本地生成可试听、可导出的 WAV 音频。模块可以独立使用，并向后续字幕模块提供段落音频与精确拼接信息。

已选引擎：GPT-SoVITS。使用已有权重进行参考音频驱动的声音克隆，仅集成推理；训练、微调及训练数据管理不在产品范围，也不列为后续任务。

已检查的运行环境：Windows 10 专业版 64 位、i5-13400F、RTX 3070 Ti 8GB、约 32GB 内存。检查时 E 盘约有 77GB 可用空间，实际安装前重新确认。

已完成的环境调整：按用户要求卸载 Python 3.13，安装 Python 3.10.11 到 `E:\Tools\Python310`；现有 Python 3.9 未改动。GPT-SoVITS、模型和依赖已部署到开发机 `E:\codoop-cast-data` 下的私有环境，不直接把依赖安装到全局 Python。该路径仅为本机实际部署位置，不是其他用户的默认要求。

## 本次范围

用户可用：保存并复用参考声音、文本或文件配音、查看已有声音、试听成品、用自然语言重做指定段落、导出 WAV。

内部实现：环境检查与按需准备、参考音频规范化、语义分段、任务状态保存、音频检查、拼接、重试及精确时长清单。这些不作为必须由用户逐项操作的功能菜单。

独立后续模块：字幕对齐与视频制作；生成后 ASR 辅助质检另行评估。参考素材的自动识别属于当前初始化流程，不能推迟后继续要求用户手动裁切及填写全文。

## Skill 入口与路由

| 入口 | 职责 | 典型请求 |
| --- | --- | --- |
| `codoop-cast-voice` | 声音保存与复用、稿件配音、局部重做 | “用这个声音读这篇稿子”“用上次的声音”“第二段重新生成” |
| `codoop-cast-setup` | 插件各功能共用的环境检查、按需初始化、配置与有界修复 | “初始化插件”“检查配音环境”“修改缓存位置” |

voice 的描述只覆盖参考声音和配音，不吸引调研、写稿或视频请求；setup 描述只覆盖本插件运行环境，不成为通用系统维护入口。SKILL.md 保持简短，详细错误及参数规则放按需读取的 references，实际操作交给固定脚本。

声名称可由文件名给出默认值并告知用户，不强制先命名。用户明确指定声音时使用该档案；只有一个档案时自动使用；多个且未指定时询问一次。当前任务可复用已经明确选择的声音，但不在存在歧义时擅自选人。

任务完成后将声音档案 ID、任务 ID 和成品路径保存到本地记录，后续“上次”“第二段”等请求通过这些记录定位；有多个可能对象时才询问。

## 使用流程

1. 用户提供参考音频和稿件，或指定已有声音及新稿件；Agent 只补问缺失的必要内容。
2. Agent 验证输入并执行环境检查。缺少依赖时，说明首次准备的下载量和位置，按已有授权及宿主权限调用 setup；已就绪则直接生成。
3. 内部保存声音档案、规范化音频和文字、按语义分段。参考语言默认按内容处理，有歧义时再询问；不强制用户检查每段或选择模型参数。
4. 内部逐段推理、检查并拼接，长任务仅展示有意义的进度；问题段保留可重试状态。
5. 自动导出完整 WAV，Agent 在宿主支持时直接呈现试听，否则给出可访问的本地文件链接。声音档案名称和复用方式用一句话说明。
6. 用户要求改读法、慢一点或重做某段时，复用档案和成功产物，只更新必要部分再返回成品；不要求用户手动挑选尝试 ID。

参考过长、多人混音或文字不对应时，说明具体问题并请求可用片段或正确文字；不默默选错人物或改写稿件。格式与时长限制依锁定版本验证，普通可解码格式转换由脚本处理。

第一版以 Agent skills 为用户入口，本地命令行作为 Agent 的执行入口，Python 函数作为内部能力。不建设 HTTP 服务或网页入口；宿主打包格式需要实际验证。

## 运行结构

```text
Agent → voice skill → 本地 CLI
          ↓
codoop-cast 配音模块（档案、任务、产物）
          ↓ Python 适配器与本地进程消息
GPT-SoVITS 独立推理进程
          ↓
分段 WAV → 格式统一与拼接 → 最终 WAV + 清单
```

- 模块直接通过 Python 函数调用；引擎在独立环境中的工作子进程运行，单次任务内复用模型，结束后释放资源，不依赖跨 Agent 消息永久存活的服务。
- 不监听端口，不启动上游 API 或 WebUI；验证直接 Python 推理调用，初期一次执行一个 GPU 生成任务。
- 适配器提供运行状态、模型信息及已验证能力。进程通过标准输入输出传递逐行 JSON 消息，大文件通过本地路径交接，日志写入 stderr 或文件。
- 第一步锁定上游提交、匹配的 GPT/SoVITS 权重组合及依赖；不混搭不同版本权重。
- 调研源：[GPT-SoVITS 官方仓库](https://github.com/RVC-Boss/GPT-SoVITS)。实际安装命令、权重名称和引擎参数在实施前对照锁定版本确认。

## 文件与数据设计

以下目录仅作维护者开发布局；发布版按[插件体验设计](05-plugin-experience.md)将运行时、缓存与用户数据放到独立可配置目录，不能写死开发机路径或写入插件安装目录。避免模型与个人音频进入源码版本管理。开发路径初稿：

```text
.venv/                          # codoop-cast 运行环境
.runtime/gpt-sovits/             # 上游代码、独立环境、模型及引擎日志
data/voices/<voice_id>/          # 原始参考音频、规范化副本
data/jobs/<job_id>/              # 文本、分段 WAV、清单、合并 WAV
data/codoop-cast.sqlite          # 档案、版本、任务与产物索引
```

实际实施前增加对应忽略规则；本计划不创建这些运行目录。本开发机下载和缓存优先配置到 E 盘；其他用户按平台用户目录或显式配置保存，不要求有 E 盘，不修改系统 Python 或全局 PATH。

源码分发结构统一采用 `skills/` 与 `runtime/codoop-cast/`，安装和引导脚本位于 `scripts/`。runtime 指随插件提供的运行代码，和用户目录中的模型、解释器环境及任务数据分开。skill 根据自身安装位置定位共享 CLI，不依赖工作目录。

| 对象 | 字段草案 |
| --- | --- |
| 声音档案 | ID、名称、版本、参考音频路径与摘要、参考文字、语言、引擎与权重标识、默认参数 |
| 配音任务 | ID、声音档案版本、原文、朗读文字、分段列表、状态、创建时间、错误 |
| 分段产物 | 段落 ID、尝试 ID、文字、WAV 路径、采样率、声道、样本数、生成耗时、检查状态 |
| 合并清单 | 段落顺序、有效尝试 ID、统一采样率、各段样本边界、插入静音样本数、总样本数、来源版本 |

任务使用提交时的档案快照；后来编辑档案不影响正在运行的任务。重做生成新尝试，保留旧音频供比较，不覆盖已成功产物。

首版“删除档案”采用归档并阻止新任务引用，已有任务和音频保持可读；永久清理文件另行设计。

CLI 对 Agent 输出 JSON，至少含 `status`、`job_id`（如适用）、`artifacts`、`next_action` 和结构化 `error`；日志写到 stderr 或文件。对用户只显示结果、必要进度和需要其处理的问题。正式子命令定稿前验证 Windows 参数、中文路径和空格路径的传递。

## 本地调用草案

以下是内部 Python 函数职责草案，不对应 HTTP 路由；具体签名在适配器验证后定稿。

| 操作 | 函数草案 | 行为 |
| --- | --- | --- |
| 引擎状态 | `get_engine_status()` | 区分未启动、加载中、就绪和故障 |
| 查询能力 | `get_voice_capabilities()` | 返回已验证参数及参考音频约束 |
| 创建档案 | `create_voice(...)` | 导入本地音频、参考文字、名称与语言 |
| 查询档案 | `list_voices()`、`get_voice(id)` | 列表与详情 |
| 编辑档案 | `update_voice(id, ...)` | 创建新版本 |
| 提交配音 | `submit_speech_job(...)` | 返回任务 ID，后台排队执行 |
| 查看任务 | `get_speech_job(id)` | 返回阶段、段落状态、产物路径或错误 |
| 单段重做 | `retry_segment(job_id, segment_id)` | 为指定段落创建新尝试 |
| 合并导出 | `export_speech_job(id, ...)` | 校验选定版本后生成 WAV 和清单 |
| 试听文件 | `get_artifact_path(id)` | 返回已登记的本地文件路径，由入口负责播放 |
| 取消任务 | `cancel_speech_job(id)` | 停止后续调度，当前推理按引擎能力结束或中止 |

读取用户选择的本地文件，验证后复制到受管理目录，不设计上传和下载机制。异常包含错误类型、可读说明及是否建议重试。

子进程消息包含请求 ID、任务 ID、动作、参数、进度、结果或错误。后台读取消息，避免阻塞操作入口；记录退出码并识别意外退出，恢复时不盲目重复生成。首版取消优先在段落边界生效，不承诺任意时刻中断推理。

## 分段、音频与恢复规则

- 以语义句群为单位切分，具体长度在真实声音测试后确定；避免逐字或过短切分。
- 同一任务使用固定档案版本和有效参数；单段重做仍需检查跨段音色与音量。
- 展示文本与朗读文本分开保存；首版支持显式修改读法，不引入完整自动读音纠错系统。
- 先保留引擎原始输出，再统一采样率、声道与 PCM 格式；目标格式在验证后锁定。
- 拼接时长根据统一格式后的样本数计算，将段间静音计入偏移；字幕模块无需猜测停顿。
- 文件检查未通过的段落不进入正式导出；用户可试听重试。
- 自动重试仅针对明确的暂时性故障，最多一次；显存不足、无效输入或权重不匹配不重复盲试。
- 进程崩溃后保留成功段，运行中的尝试标记为中断；恢复时只补齐缺失段。
- 文件先写临时位置，校验后再登记有效产物；导出失败不替换上次成功版本。
- 精确重现相同波形不作为承诺，保存版本与参数用于追踪。

## 验收样例

| 样例 | 关注点 |
| --- | --- |
| 约 15 秒日常中文 | 音色相似、停顿自然、无明显漏读与重复 |
| 数字、日期、单位、英文缩写混排 | 展示与朗读文字对应，问题读法可修改并重做 |
| 约一分钟知识口播 | 多段连贯、音量协调，最终文件完整可播放 |
| 无效或静音参考音频 | 生成前提示错误，不留下“成功”任务 |
| 单段重做 | 未选中的旧尝试可追溯，其他成功段文件不变 |
| 引擎不可用或显存不足 | 提示原因、保留产物，恢复后可继续 |
| 取消及进程重启 | 状态可解释，不自动重复已完成生成 |
| 首次通过 voice 调用 | 自动检测并按需初始化，完成后继续原配音请求，无须用户先手动运行 setup |
| 再次使用同一声音 | 不重复准备环境，不重新索取已保存的参考素材 |
| 多档案未指定声音 | 只询问必要选择，不随意使用某个人物声音 |
| 中文/空格路径与任意工作目录 | skill 能找到 runtime，素材可读取，成品有可用绝对路径 |
| 其他用户安装及插件升级 | 不依赖开发机路径，不覆盖档案和作品，不要求修改全局 Python |

声音自然度和相似度由用户试听评价，不虚构客观评分阈值。性能记录硬件、稿件长度、成品时长、冷启动/热生成耗时及显存峰值，实际速度验证后再制定目标。

有意义的自动检查限定为输入验证、状态恢复、段落版本选择、音频样本与偏移一致性；真实模型质量依靠实际音频验证，不用模拟推理代替。

- V0 明确插件清单和共享代码位置；V5 完成 skill 打包；V6 验证干净环境首次使用及再次使用，维护者机器跑通不等于插件可交付。

- 一段本人或已获授权的清晰参考音频，以及准确参考文字；没有用户素材时，仅用许可明确的示例验证技术链路，不据此判断目标声音相似度。

- 默认语速、段间停顿和分段策略：V1 试听后确定。
- Agent 范围已确定参考 codoop-flow：Codex、Claude Code、Cursor；具体宿主版本和安装命令通过打包测试确认。

本计划已获用户授权进入实现；尚未完成的发布和硬件验收不得标为已通过。
