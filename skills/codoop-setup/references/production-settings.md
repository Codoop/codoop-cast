# Shared production settings

Before planning or authoring video, run `config show --directory <content-project-or-batch>` through the shared runtime. Read both `output_language` and the fully resolved `video` object. Follow [language](language.md) for prose and speech language; English instructions do not imply English artifacts.

Video preferences merge by field: built-in defaults, legacy project output defaults, shared private config, ancestor project/batch configs from outermost to nearest, then explicit current-task overrides. An unspecified font, frame rate or avatar field inherits instead of resetting. The active shared file remains `config.json`; project/collection overrides remain `.codoop-cast/config.json`.

The `video` object supports `orientation` (portrait/landscape/square), `resolution` with actual pixel width/height, positive integer `fps`, partial `subtitle_style` and partial normalized `avatar` settings. Defaults are portrait 1080×1920/30fps with the established caption/placeholder settings. Resolution must contain both positive even dimensions for yuv420p export. Explicit dimensions and orientation must agree. Orientation alone reorders existing dimensions; square uses the shorter side. Switching from square to a nonsquare canvas requires explicit dimensions. Dimensions alone determine orientation. Do not invent unsupported codec/bitrate/platform fields.

For a saved preference, write an agent-managed UTF-8 JSON patch containing video fields only, then run `setup [--directory <scope>] --video-config-file <patch.json> [--output-language <tag>]`. This configures without feature/model installation. Users can simply say “default to landscape 1920×1080”; do not ask them to edit JSON. Repeated setup preserves unrelated settings and dependencies. `config show --video-config-file <patch.json>` previews the task overlay without saving.

For one production request, pass the overlay to `produce plan --video-config-file <patch.json>`. Read the returned pinned `video`; carry the same task patch to `storyboard prepare --video-config-file <patch.json>`, or create a precise explicit output-profile artifact from the pinned values and import it with `--profile-file`. These two prepare options are mutually exclusive. Without an explicit profile, prepare derives output-profile.json from current resolved preferences rather than hardcoding portrait. A supplied output-profile file is the explicit task specification and preserves its identity.

New visual workflow plans snapshot effective video settings. A relevant effective change requires replanning; task overrides remain effective for fields they specify. Configuration-only changes that resolve to the same values do not require new output. Research/speech-only plans need not restart because the video format changed. Ready selected visual packages that conflict with explicit video configuration are rebuilt, not reused. Storyboard/scenes/export checkpoints verify their actual profile against the pinned specification when video preferences are explicit. Old plans without a video snapshot remain readable, and old imported packages are not silently rewritten merely to add a default.

The storyboard chooses information density/layout using the target aspect. For a format-only change preserve script, source facts, semantic scene intent and narration; revise output-profile and dependent visual references/versions. Reuse media when suitable, avoid redundant image generation, and register updated dependencies. Scenes implement real relayout and use the exact profile. Captions/avatar layout is visually checked, not assumed correct from dimensions alone.

Compile/render consumes the production package's pinned output-profile. Never reread defaults mid-render to silently override a prepared package. A supplied complete package is an explicit specification; if the user asks to apply changed defaults, create/adapt a new working package and validate before rendering. No registered artifacts are modified in place. Profile validation is not proof of successful layout, typography or audiovisual quality.
