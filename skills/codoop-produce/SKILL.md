# Project production

Before producing content, read the shared [production settings](../codoop-setup/references/production-settings.md) for language, aspect, resolution, fps, captions and avatar configuration. Follow the shared [artifact language policy](../codoop-setup/references/language.md). Resolve the configured target language; the English instructions do not imply English deliverables.

This is the host Agent's workflow skill. It calls existing independent skills; the local produce commands persist plans/checkpoints and do not autonomously search, write, synthesize or render. Single projects and persistent sequential batches use the same per-project workflow; no HTTP service or background scheduler is required.

Resolve the plugin root two directories above this SKILL.md's real path. Follow the shared [project layout](../codoop-setup/references/project-layout.md) and read [execution](references/execution.md) for commands and stage handoffs. For multiple topics/projects, read [batch queue](references/batch.md) and use it to coordinate projects rather than duplicating the stage logic.

1. Locate the user's content project. Inspect current selections and existing task context. Explicitly accepted candidates can be selected through project select; do not infer acceptance from the largest version number. Import explicitly supplied external artifacts through their owning skill rather than requiring earlier stages. Ask only for a genuinely missing folder, voice choice, topic or other necessary input.
2. Determine the requested target (default exports) and actual change scope. Run produce plan. It reuses valid selected outputs and expands only missing/affected prerequisites. For a requested revision pass the changed stage via --force; rebuilding voice must not regenerate research, script or scenes. Review partial/invalid inputs rather than treating them as complete; if needed repair/import to a new ready version and re-plan.
3. Execute available stages using the corresponding installed skill: research, script, storyboard, assets, voice, subtitles, scenes and video. The assets step is internal agent work: choose suitable existing/local/generated visuals without requiring user material management. Use produce start before work; retain its candidate output path and returned run ID. The plan is an execution outline, not a fixed visual template or requirement that every task start with research. Agent creative judgment and actual artifact schemas still apply.
4. Validate real stage outputs through their skill. Record actual source dependencies when registering the new version. Then produce checkpoint selects the completed version and stores its identity and optional task ID. Complete only what truly succeeded; a plan/status JSON, screenshot preview or unreviewed partial result is not a finished video. Preserve known user approvals for unchanged inputs without asking again.
5. On errors, record produce fail with the concrete cause/task ID. Inspect logs and task state before one targeted retry or resume supported by the owning skill. Do not restart a running task merely because the chat resumed. Recovery creates a new version when an unfinished output path exists. If sources/selection or saved plan changed, re-plan; never silently continue with mismatched inputs.
6. Before final export, assemble exact selected scene and subtitle artifacts, verify script revisions match and compile/render through video skill. Keep requested aspect, dimensions, caption style and avatar location in output-profile. Inspect screenshots/layout and audio/subtitle timing; machine checks cannot prove pronunciation, facts or editorial quality. If current context authorizes a full draft video, finish it without adding approval steps; label new content as a draft when it has not been reviewed.
7. Return the actual MP4 and editable production directory, state which accepted inputs were reused, and disclose only material unresolved issues. Do not publish to a platform, message anyone or claim new audio/visual approval. For a single project stop when its requested target is delivered. For batches continue through the requested queue, preserving unresolved items and delivering a summary. Asset preparation is an automatic stage before new scenes; an empty collection is valid for code-only visuals. Use --force assets for replacements so audio and subtitles remain reusable.
