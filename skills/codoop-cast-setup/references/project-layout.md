# Content project layout

Apply this convention to every codoop-cast skill. A content project is the user-selected working folder, separate from the installed plugin and shared dependency/model data. One project normally holds one topic/content item with multiple export formats. The folder's display name may contain Chinese/spaces; do not rename the user's folder. Managed names below are lowercase ASCII, hyphenated when multiword.

## Locate and initialize

From the requested working directory, run `project status --directory <folder>`; discovery walks upwards to the nearest cast-project.json. If none exists and the user is creating content in this folder, run `project init --directory <selected-folder> [--name <display-name>]`. Do not initialize the installed plugin directory, home directory, or another unrelated folder merely because a shell starts there. If the user has not selected a folder and none is available from task context, ask for its location. Existing stand-alone packages remain supported as explicit imports; do not silently move or rewrite them. Project management itself is stdlib-only and does not install any feature environment.

```text
project init --directory <project-root> [--name <display-name>]
project status --directory <project-root-or-child>
project path --directory <project-root> --stage research
project register --directory <project-root> --stage research --version v001 [--state partial] [--depends-on <stage>=<version> ...]
project select --directory <project-root> --stage research --version v001
```

`project index --package ...` remains the existing production artifact-hash command; it is not content-project initialization or version selection.

## Fixed names

Create only needed stage directories. Each completed stage version has version.json generated by project register, plus:

| Stage | Canonical primary files |
| --- | --- |
| research/v001/ | report.json, report.md, checks.json, sources/ |
| script/v001/ | script.json, script.txt (plain narration), script.md (readable review) |
| storyboard/v001/ | video-script.json, storyboard.md |
| assets/v001/ | assets.json, files/<asset-id>.<ext> |
| voice/v001/ | narration.wav, narration.json (existing speech export manifest), original.txt, narration.txt |
| subtitles/v001/ | alignment.json, subtitles.srt, audio.json, script.json, checks.json, media/narration.wav, raw/ diagnostics |
| scenes/v001/ | scene.json, files/index.html; local support files under files/ |
| exports/v001/ | video.mp4, production/ (complete compiled package), video-qa/render.json and renderer screenshots/log |

Root marker: cast-project.json; internal work: .cast/work/<task-id>/; optional local job references: .cast/jobs/<task-id>.json; persistent workflow plans/checkpoints: .cast/runs/<run-id>/plan.json and state.json. Shared model/browser/Python caches, voices and actual runtime task logs stay in CODOOP_CAST_HOME. Do not copy personal reference recordings/models into a shareable content project by default.

Source snippets use sources/<source-id>.md or the preserved source extension. Assets use their existing stable asset ID as filename; list origin/original filename in metadata. Additional figures/notes are allowed under the owning stage's version, with descriptive lowercase kebab-case names. Generated raw diagnostics preserve the generating tool's filenames and format. Renderer screenshots use the existing NN-<scene-id>.png convention. No output names such as final-final, latest, temp2 or unexplained duplicate suffixes.

A stage can retain self-contained dependency snapshots (script.json, assets.json, output-profile.json, package.json, media/ etc.) required by existing independent commands. These are exact pinned input copies, not separately edited upstream truth. Register direct upstream dependencies in version.json. HTML supporting files must still be declared as assets so compilation copies them. Production's canonical eight artifact names remain unchanged inside production/.

## Version lifecycle

1. Read explicit selections from cast-project.json current. Null means unavailable; never select by largest version number or file mtime. Use selected ready/partial inputs with their actual caveats, and reject invalid inputs. If selected inputs are stale, reconcile them with the user's requested scope before making new output.
2. Obtain the next path via project path. It returns an uncreated candidate such as research/v002, not a reservation. Concurrent writers must retry with a fresh path if it becomes occupied; existing commands reject existing outputs. Version numbers are v001, v002, ... v999, v1000; no resets or renumbering. Skipped failed versions are allowed.
3. Generate the requested stage into that new directory with existing independent commands. Agent authors missing creative artifacts. Do not write in-place over a registered version. Put editable drafts, previews and temporary assemblies under .cast/work/<task-id>/; a draft may be edited until registration. Before exporting a render, compile into exports/vNNN/production/, then render to exports/vNNN/video.mp4, which creates video-qa/ automatically.
4. Run the stage-specific validator and inspect its actual results. project register enforces filenames and file integrity, not semantic schema validity, factual truth, audio quality or user approval. Do not register incomplete/failed work as ready. Preserve partial research state with --state partial. Partial cannot mean successful final MP4.
5. Register the finished directory with the exact direct dependencies actually used, e.g. script/v002 depends on research=v001. Stage version.json records relative file hashes and dependency version manifest hashes. Registration does not select the new version or modify upstream artifacts. Do not add more files after registering.
6. Select the version when it is the result requested/accepted for further use in the current task. Routine successful task completion need not add an approval step; if editorial review is pending, preserve the prior selection and show the new candidate. Historical user approvals remain scoped to their actual input versions.

Folder version vNNN identifies a stage execution and is independent of each artifact's revision. Preserve artifact IDs and increment revisions when content changes; copied inputs retain their IDs/revisions. Do not rewrite JSON revisions merely to match directory numbers. version.json lists files inside its own directory, not itself. Never edit it or cast-project.json current by hand; use register/select commands.

project status reports selected stages as missing/ready/partial/stale/invalid. Stale means direct or transitive dependencies refer to a version different from the current selection. Invalid includes changed/missing/unrecorded output files or changed dependency manifests. Status does not regenerate anything and does not claim approval. Retain historical versions; clearing them is separate user-directed work. Moving the whole folder preserves project references, while legacy engine manifests may still contain private job paths and should not be described as completely reproducible on another machine.

## Current CLI adapters

- research export: output the whole report package to research/vNNN/.
- storyboard prepare: output to storyboard/vNNN/, then Agent writes video-script.json and storyboard.md before validating/registering.
- speech generate/export: prefer --script-file <script/vNNN/script.json> --output voice/vNNN/narration.wav. Structured export also writes narration.json, script.json, original.txt and narration.txt into that version. Legacy plain-text export still copies only WAV; copy its returned manifest/text artifacts explicitly if needed. The engine narration.json is not the standard audio.json; subtitles generates that standard artifact.
- subtitles generate: --output subtitles/vNNN/; keep its self-contained handoff and original internal paths.
- scenes: author files/index.html and scene.json in scenes/vNNN/, plus required pinned input artifacts. Preview in .cast/work/, not in a registered version.
- video compile: --output exports/vNNN/production/. Then video render --output exports/vNNN/video.mp4. Keep its generated video-qa/ directory. Register exports only after checks and MP4 exist.
- script export: --output script/vNNN/ produces script.json, script.md, script.txt, spoken.txt, checks.json, script-source.json and retained inputs/. Dedicated assets skill is not implemented yet; assets naming is reserved.

Shared artifact-language defaults and optional locale dictionaries live in `.codoop-cast/config.json` and `.codoop-cast/locales/<tag>.json` at the project or batch collection root. Resolve them using the [language policy](language.md). They are configuration, not versioned stage outputs; changing language requires new affected content versions.
